# 谁最圆

《谁最圆》微信小游戏 v0.5 —— 画一个圆，越圆分越高。

同一份 `game.js` 双端运行：微信小游戏（`wx.*`）与浏览器（DOM / Pointer Events），
逻辑坐标统一按 750×1624 设计稿，缩放与安全区适配由渲染层处理。

## 版本变更

- **v0.5**：结算卡片去掉底部两行——「形状偏了，圆度扣了 X 分」类诊断文案与
  「距饺子还差 9.1 分」类升级提示。卡片只留分数、段位、评语三行，高度 398→324。
  诊断与升级提示的**计算逻辑保留**（`diagnose()` / `upgradeTip()`，仍被单测覆盖），
  只是不再渲染；缺口橙色虚线、拟合圆虚线等画在圆上的可视化提示不受影响。
- **v0.4**：去掉实时反馈（边画边给分 + 笔迹三色着色），笔迹全程单色墨线。
  原因：着色阈值按半径固定百分比（1.2% / 3%），手机上手抖 3px 即触发，
  87 分的正常笔迹也有 42% 飘黄；而 63 分的椭圆有 73% 显示为红色 ——
  **颜色与分数严重脱节**，玩家会被误导。且拟合圆每 90ms 重算，已画的线段会被反复改判。
  评分只在松手后算一次，笔迹不再变色。
- **v0.3**：移除全部音频（BGM / 音效 / 静音开关），反馈只走视觉 + 新纪录轻震动。

## 评分引擎（v0.2）

> **实现位置：`shared/scoring.js`** —— 评分与防作弊判定的**唯一实现**，主域（`game.js`）与
> 未来的云函数共用同一份，保证两端算出的分数逐位一致。
> 约束：**纯函数模块**，不得引用任何平台全局对象、不得读写存储（云函数与小游戏主域没有共同的
> 平台 API，一旦混入宿主调用，"共享"就失效了）。UMD 包装，CommonJS 与浏览器全局 `Scoring`
> 同时可得，共 24 个导出符号。
> 改动后必须跑 `who-is-circle-tests` 的 `npm test` 与 `npm run test:e2e`。

分数 = **R(圆度) × C(闭合) × D(方向)**，三者都在 0～1 之间，因此分数天然覆盖 0～100 全区间。

**① 预处理**：按 4 设计px 等弧长重采样（消除手速快慢造成的采样密度偏差），
再以中心化 Kasa 圆拟合求圆心/半径，用 Landau 几何迭代做一次修正。

**② 圆度 R(ε)**：ε = 径向残差 RMS / 半径。用锚点表 + log 插值映射到分数——
误差每翻一倍，体感均匀变差，扣分也大致均匀：

| ε | 0.001 | 0.005 | 0.01 | 0.02 | 0.05 | 0.08 | 0.12 | 0.25 | ≥0.5 |
|---|---|---|---|---|---|---|---|---|---|
| R | 100 | 97 | 92 | 84 | 65 | 50 | 35 | 10 | 0 |

**③ 闭合 C(θ)**：θ 为累计有向角（画超一圈只评第一圈）。缺口 ≤5° 不扣分，
其余按 `1 − ((360−θ−5)/270)^0.8` 折算。

**④ 方向 D(b)**：b 为反向步长占比。反向判定用**叉积**（半径向量 × 弦向量）符号，
不用角度差符号——拟合圆心差 1px 就会把 24% 的正常步长误判成反向（实测会白扣 27 分）。

**⑤ 扣分明细**：`loss = {round, close, dir}`，三项之和恒等于 `100 − score`。
v0.5 起结算卡片只保留「分数 + 段位 + 评语」三行，不再显示扣分诊断与升级提示。

**无效判定**（不进入 0～100 区间，给出具体原因）：直线 / 太小 / 太短 / 只画了一小段弧。
其中「一小段弧」与「乱涂」用 `路径长度 / 拟合周长` 区分：干净的小弧判无效，
乱涂（路径长度远超周长）判有效但进「灾难现场」0 分档，不浪费一次吐槽。

## 防作弊（纯前端第一阶段）

> 判定逻辑（`guardCheck` / `judge` / `shapeSig`）已移入 `shared/scoring.js`；`game.js` 只保留
> 采集侧信号（`DEV` 豁免开关、`SIG` 采样参数、`pushRaw`）。
> `judge(r, g, replay, dev)` 的第 4 参数控制"是否豁免风险判定"——开发预览传 `DEV`，
> 服务端不传（即不豁免）。**缺省值是"不豁免"**，避免正式版误伤真人。

目标：挡住低成本作弊（改存储 / 控制台伪造 / 脚本灌入 / 匀速自动画圆），**且不误伤真人**：
可疑成绩照常显示，只是不计入最佳、不出分享卡。局限：解包改代码挡不住，只能拖慢——
真正的高分榜仍需要服务端重算。

- **输入真实性**：事件时间戳与回调真实时长的偏差、采样间隔变异系数、重复时间戳占比。
- **行为特征**：中段速度变异系数、起笔/收笔的加减速斜率、径向残差低频能量占比、
  二阶差分粗糙度（人手必有微颤，程序圆过于干净）。
- **轨迹指纹**：取 64 个等距样本的归一化径向残差（`number[64]`，非哈希），与本地最近 50 局
  逐元素求平均绝对偏差，识别「重放同一形状」。
- **存档自校验**：最佳成绩同时保存笔迹；读取时重算分数，对不上说明分数被改过。
- **判定策略**：风险分 ≥10 且命中 ≥2 条 → 判 `shadow`（不计入最佳）；≥5 → 判 `unverified`（不出分享卡）。
  单条弱信号不定罪——真人笔迹实测风险分 3，机器笔迹 18。

## 开放数据域（好友榜的数据边界）

好友的昵称、头像、分数属于**关系链数据**，微信只允许在**开放数据域**（一个独立的 JS 沙盒）里读取。
主域拿不到这些数据本身，只能把开放数据域画到离屏画布 `sharedCanvas` 上的内容贴出来。

```
game.json      "openDataContext": "open-data"   ← 值是子目录名，不是路径
open-data/     开放数据域代码（独立沙盒）：
               · 能调 wx.getFriendCloudStorage / wx.getUserCloudStorage
               · 不能 require 主域、没有 getApp、不能发网络请求、不能加载远程图片
game.js        主域：wx.getOpenDataContext().canvas → ctx.drawImage(sharedCanvas, ...)
```

**踩过的坑，记一下**：

- `openDataContext` 写错目录名**不会报错**，只是开放数据域静默不加载 —— 最难查的一类故障。
  所以有守卫测试盯着（`who-is-circle-tests/unit/opendata.test.js`，含目录存在性、
  沙盒隔离、API 越界三类断言）。
- 离屏画布**只能画到上屏画布上**；上屏画布不能 `toDataURL`，其 context 不能 `getImageData`。
- 非微信环境（浏览器调试页、Node 单测）没有这些 API —— 主域一律**静默降级**：不贴图、不报错。
- 开放数据域的代码**不得引用主域符号**，且注释里提到的 API 名也不算调用
  （守卫测试会剥离注释后再查，避免自己把自己搞红）。

> 当前进度：**P4 已完成**。`open-data/board.js` 是纯逻辑（解析/排序/名次/截断/绘制，
> Node 里可单测），`open-data/index.js` 负责 wx 那部分（拉数据、头像、消息、重画）。
>
> **同目录 `require` 是允许的**（主域 ↔ 开放域互相 require 才是禁止的）——
> 纯逻辑能拆出来、能单测，全靠这一条。越界 require（`../`）会让整个开放数据域
> 加载失败、榜面一片空白，是最难查的一类故障，所以有守卫测试盯着。

## 审计记录的清理（与隐私声明对齐）

`submissions`（每次提交的审计记录）**只保留 30 天** —— 隐私保护指引里就是这么声明的，
不删就是骗用户。清理由独立的云函数 `cleanup` 干，配**定时触发器**（每天凌晨 3 点）。

```
cloudfunctions/cleanup/
├── core.js        ← 纯逻辑（过期判定 / 切批 / 计划），Node 可单测
├── index.js       ← 云函数入口（分批删，每批 100 条，单次最多 20 批）
└── README.md      ← 部署 + 触发器配置 + 行为要点
```

部署与触发器配置见 `cloudfunctions/cleanup/README.md`（**`--remote-npm-install` 不能省**）。

## 云端算分（好友榜的权威分）

榜上的分**不是客户端算的**，是云函数 `score` 算的。客户端那份只作交叉校验参考
（出参 `scoreDelta` 就是两者之差）。

```
cloudfunctions/score/
├── index.js    入口：初始化 SDK、确保集合存在、适配 db 接口
├── core.js     全部逻辑（**不依赖 wx-server-sdk** → 可被单测直接跑，用内存 db 覆盖全流程）
└── scoring.js  构建产物：npm run sync:cloud 从 shared/scoring.js 拷贝
```

**两份算法必须永远一致** —— 云端改了分、客户端没改，比分就对不上。
所以拷贝是机械的、不允许手改，一致性由 sha256 守卫测试盯着
（`who-is-circle-tests/unit/cloudfn.test.js`）。改完 `shared/scoring.js` 记得 `npm run sync:cloud` 再部署。

**云端只信自己重算的**：客户端上报的 `guard` **不参与判定**，只回显供审计对比 ——
客户端代码在攻击者手里，"客户端说自己有问题"的判断能被摘掉。

**`clock_drift` 在云端不生效**（上传协议不带回调时刻 `h`）——这是**明确取舍**，
出参 `cloudGuard.note` 里明写着，详见 `cloudfunctions/score/README.md`。

**集合不需要手工建**：入口会在首次调用时自动创建。索引也不需要 ——
云数据库的 `orderBy` 强制要求索引，而 SDK 没有建索引的接口，所以查询刻意只用 `where` + 内存排序。

**云调用没有微信上下文**，所以另有一条**干跑（`__selftest`）通道**：
只算分不落库、身份固定为 `__selftest__`，用来验证「云端算的分 == 客户端算的分」而不污染榜单。

**⚠️ 改完云函数要重新部署，否则客户端拿不到 `best`**：
托管数据写的是云端出参的 `best`（权威有效最高分）。云函数没更新时出参里没有 `best`，

## 客户端上报链路（好友榜的权威分怎么进到榜上）

榜上的分**不是客户端算的**，是云函数 `score` 算的。P2 把云端算分做完了，P3 把它接上：

```
本地算出 S，本地历史最高 H
  ├─ S ≤ H ──→ 不上传，直接结算（这一局无论真假都上不了榜，云端没必要知道）
  └─ S > H ──→ 上传
       ├─ S ≥ 95 ──→ 同步：结算页等云端结论（高分才有防作弊价值，值得等）
       └─ S < 95 ──→ 异步：不阻塞 UI，失败进 pending 队列
```

代码在 `js/cloud.js`（**独立模块**：平台依赖全部注入，不碰 `wx` 等任何全局，
所以 Node 里能用假实现把 6 条分支全跑一遍）。

**托管数据**（`wx.setUserCloudStorage`，主域直接调，开放数据域不必参与）：

```js
{ KVDataList: [{ key: 'circle', value: JSON.stringify({
    wxgame: { score: Math.round(云端权威最高分 × 10), update_time: Unix 秒 },  // Int32 要求
    level: 段位索引,
    v: 'ok'            // verdict 标记：'ok' | 'unverified'
}) }] }
```

- `wxgame.score` 是 **Int32** → 分数一位小数，所以上报 **×10**、显示 ÷10。
- `score` 写的是**云端权威最高分**（云函数出参的 `best`），不是本局分 ——
  `wxgame.score` 是小游戏中心/排行榜的标准字段，语义就是"最好成绩"；
  写本局分会让 `score`（按本局）与 `level`（按最高分）口径打架，榜面会出现"80 分 · 大师段位"。
- `level` 放在 `wxgame` **同级**（`wxgame` 下不允许自定义字段），按最高分算。
- `v` 带 verdict：设计文档要求 `unverified` 的分要给但标出"未完全验证"。
  开放数据域读不到 `submissions`（不能发网络请求），所以那个角标只能靠托管数据自己带。
- `key` 是 `circle`：≤8 字符且全英文，后台排行榜配置要对得上。

**降级路径**（每一条都不弹错误、不打断玩法）：

| 情况 | 分数显示 | 新纪录徽章 | 本地最佳分 | 上榜 |
|---|---|---|---|---|
| 没破纪录 | 本地分 | 无 | 不变 | 否（本来也上不了） |
| 云端确认 `ok` / `unverified` | **云端分** | 有 | = 云端分 | 是 |
| 云端判 `shadow` / `reject` | 本地分（照常显示） | **无** | **不变** | 否 |
| 云端不可达（网络/未部署/超时） | 本地分 | 有（照常） | 照常更新 | 否 |
| 异步失败 → 下次启动补传 | 本地分 | 有 | 照常更新 | 补传成功后才上 |

**pending 队列**：失败的那一局（分数 + 压缩笔迹）存本地，下次启动自动补传，传完删除；
上限 5 条，超出丢最旧的。补传按顺序来 —— 云端有速率限制（60 秒 5 次），一次性全甩过去容易被限流。

### 两处明确取舍（别当成 bug）

1. **云端不可达 ≠ 作弊证据。**
   设计文档写的是「云端不可用 → 本地最佳分不更新」，实现上没照抄：
   服务不可达时按**单机行为**走（最佳分照常更新、徽章照常弹），只是这一局不上榜。
   理由：开发者工具预览里云函数可能根本没部署，照抄的话玩家永远看不到新纪录徽章；
   而「没连上服务」本来也证明不了这一局有问题。云端**明确**判无效（`shadow`/`reject`）时则是严格的 ——
   不弹徽章、最佳分不变、不上榜。

2. **开发版（`DEV`）里云端结论只作提示，不改本地行为。**
   服务端**没有**开发豁免（`judge(r, g, replay, false)`），开发者自己的合成笔迹会被云端判成 `shadow`。
   所以开发版沿用本地 `judge()` 那套豁免：云端照常调、数据照常上，但结论不改本地表现。
   正式包（`release`/`trial`）里云端结论是权威的。

> 当前进度：**P3 完成**。榜面渲染是 P4（开放数据域），入口与榜面 UI 是 P5。

### P3：真实 OPENID 落库

真机调试连上，用**手机上的微信号**（真实登录账号）画一个**破纪录**的圆：

- 首次玩没有本地最佳分 → 任何分都算破纪录 → 触发上报
- 想确定走同步路径：**画 ≥95 分的圆**（<95 走异步，异步失败不阻塞 UI，界面上看不出区别）

日志里按顺序会出现三行（`[cloud]` 前缀）：

```
[cloud] → 请求云端算分 score=97.3 pts=88 模式=同步
[cloud] ← 云端结论 status=ok score=97.3 verdict=ok 托管数据=成功
[cloud] 托管数据写入成功 key=circle score=97.3
```

云端不可达时第二行会是 `status=unavailable reason=...`，并多一行 `[cloud] pending 入队：当前 1 条`。

**判定表**（三个地方对得上才算通）：

| 看哪里 | 期望 | 怎么查 |
|---|---|---|
| 云函数日志 | 一条 `score` 调用 + 返回的 verdict | 开发者工具 →「云开发」→ 云函数 `score` → 日志 |
| 数据库 `scores` | 一条 `_id` = **真实 OPENID**（不是 `__selftest__`）的记录 | 云开发控制台 → 数据库 → `scores` |
| 数据库 `submissions` | 对应提交，含 `verdict` 字段 | 同上 → `submissions` |
| 托管数据 | key=`circle`，`wxgame.score` = **云端权威最高分** ×10 | 云开发控制台 → 存储 → 用户数据 |

**四个容易误判的点**：

1. **徽章弹不弹不能作为链路通不通的依据。** 开发版里云端结论只作提示（DEV 豁免），徽章照弹 ——
   "徽章弹了"不证明云调用成功（可能是 unavailable 降级）。真正的判据是**数据库里有没有那条真实 OPENID 的记录**。
2. **`scores` 里有记录 ≠ 这一局有效。** 云端 `scores.score` 是**有效**最高分
   （`shadow`/`reject` 不计入，见 P3.5 的口径），但 `submissions` 里那次提交仍留有 `verdict=shadow`
   的审计记录 —— **判某一局的有效性要看 `submissions` 的 `verdict`**，`scores` 只反映最高分。
3. **画得太圆反而不上榜。** 云端 `judge()` 里 `score >= 99 && risk > 0` ⇒ `shadow`
   （"太完美 = 像机器人"）。手抖一点反而更容易判 `ok` —— 这不是 bug，是防作弊规则。
4. **速率限制 60 秒 5 次。** 连着玩超过 5 局，第 6 局起会被判 `reject` + `reason=rate_limit`：
   `submissions` 里有记录，但 `scores` 不更新（限流分支直接返回）。隔 60 秒再玩一局即可验证。

## 可测试化

纯函数集中在 `shared/scoring.js`（24 个导出符号），`game.js` 末尾以 `module.exports` 转出同一批符号
（`evaluate / resample / kasaFit / winding / roundScore / closeFactor / largestGap / getRank /
diagnose / upgradeTip / guardCheck / shapeSig / isReplay / stat / judge / encodePts / decodePts /
fnv / BEST_SALT / RANKS / SCORE_CFG / GUARD_CFG / INVALID_TIPS`），Node 下 `require` 即可跑单测，
无需画布；浏览器分支的输入绑定在无 `window` 时直接跳过。

`shared/scoring.js` 与 `game.js` 导出的是**同一批函数对象**（不是副本），
`unit/shared.test.js` 用 `===` 断言这一点——防止有人又在 `game.js` 里留一份本地副本导致两端算法漂移。

## 小游戏适配要点

- 图片加载走 `wx.createImage()`，小游戏环境无全局 `Image`。
- 屏幕信息走 `wx.getWindowInfo()`，低版本基础库回退 `wx.getSystemInfoSync()`。
- v0.3 已移除全部音频：不需要 `InnerAudioContext`、不需要 WebAudio、不需要音频素材。
- 触摸事件 clientX 是逻辑 px，需乘 `canvas.width / windowWidth` 换算成物理 px 再进统一坐标转换。
- `index.html` / `README.md` / `.eslintrc.js` 已在 `packOptions.ignore` 中排除，不进包。
