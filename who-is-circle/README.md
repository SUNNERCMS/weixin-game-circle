# 谁最圆

《谁最圆》微信小游戏 v0.5 —— 画一个圆，越圆分越高。

同一份 `game.js` 双端运行：微信小游戏（`wx.*`）与浏览器（DOM / Pointer Events），
逻辑坐标统一按 750×1624 设计稿，缩放与安全区适配由渲染层处理。

## 版本变更

- **v0.5**：结算卡片去掉底部两行——「形状偏了，圆度扣了 X 分」类诊断文案与
  「距饺子还差 9.1 分」类升级提示。卡片只留分数、段位、评语三行，高度 398→324。
  诊断与升级提示的**计算逻辑保留**（`diagnose()` / `upgradeTip()`，仍被单测覆盖），
  只是不再渲染；缺口橙色虚线、拟合圆虚线等画在圆上的可视化提示不受影响。
- **v0.4**：去掉实时反馈（边画边给分 + 笔迹三色着色），笔迹全程单色墨线。
  原因：着色阈值按半径固定百分比（1.2% / 3%），手机上手抖 3px 即触发，
  87 分的正常笔迹也有 42% 飘黄；而 63 分的椭圆有 73% 显示为红色 ——
  **颜色与分数严重脱节**，玩家会被误导。且拟合圆每 90ms 重算，已画的线段会被反复改判。
  评分只在松手后算一次，笔迹不再变色。
- **v0.3**：移除全部音频（BGM / 音效 / 静音开关），反馈只走视觉 + 新纪录轻震动。

## 评分引擎（v0.2）

> **实现位置：`shared/scoring.js`** —— 评分与防作弊判定的**唯一实现**，主域（`game.js`）与
> 未来的云函数共用同一份，保证两端算出的分数逐位一致。
> 约束：**纯函数模块**，不得引用任何平台全局对象、不得读写存储（云函数与小游戏主域没有共同的
> 平台 API，一旦混入宿主调用，"共享"就失效了）。UMD 包装，CommonJS 与浏览器全局 `Scoring`
> 同时可得，共 24 个导出符号。
> 改动后必须跑 `who-is-circle-tests` 的 `npm test` 与 `npm run test:e2e`。

分数 = **R(圆度) × C(闭合) × D(方向)**，三者都在 0～1 之间，因此分数天然覆盖 0～100 全区间。

**① 预处理**：按 4 设计px 等弧长重采样（消除手速快慢造成的采样密度偏差），
再以中心化 Kasa 圆拟合求圆心/半径，用 Landau 几何迭代做一次修正。

**② 圆度 R(ε)**：ε = 径向残差 RMS / 半径。用锚点表 + log 插值映射到分数——
误差每翻一倍，体感均匀变差，扣分也大致均匀：

| ε | 0.001 | 0.005 | 0.01 | 0.02 | 0.05 | 0.08 | 0.12 | 0.25 | ≥0.5 |
|---|---|---|---|---|---|---|---|---|---|
| R | 100 | 97 | 92 | 84 | 65 | 50 | 35 | 10 | 0 |

**③ 闭合 C(θ)**：θ 为累计有向角（画超一圈只评第一圈）。缺口 ≤5° 不扣分，
其余按 `1 − ((360−θ−5)/270)^0.8` 折算。

**④ 方向 D(b)**：b 为反向步长占比。反向判定用**叉积**（半径向量 × 弦向量）符号，
不用角度差符号——拟合圆心差 1px 就会把 24% 的正常步长误判成反向（实测会白扣 27 分）。

**⑤ 扣分明细**：`loss = {round, close, dir}`，三项之和恒等于 `100 − score`。
v0.5 起结算卡片只保留「分数 + 段位 + 评语」三行，不再显示扣分诊断与升级提示。

**无效判定**（不进入 0～100 区间，给出具体原因）：直线 / 太小 / 太短 / 只画了一小段弧。
其中「一小段弧」与「乱涂」用 `路径长度 / 拟合周长` 区分：干净的小弧判无效，
乱涂（路径长度远超周长）判有效但进「灾难现场」0 分档，不浪费一次吐槽。

## 防作弊（纯前端第一阶段）

> 判定逻辑（`guardCheck` / `judge` / `shapeSig`）已移入 `shared/scoring.js`；`game.js` 只保留
> 采集侧信号（`DEV` 豁免开关、`SIG` 采样参数、`pushRaw`）。
> `judge(r, g, replay, dev)` 的第 4 参数控制"是否豁免风险判定"——开发预览传 `DEV`，
> 服务端不传（即不豁免）。**缺省值是"不豁免"**，避免正式版误伤真人。

目标：挡住低成本作弊（改存储 / 控制台伪造 / 脚本灌入 / 匀速自动画圆），**且不误伤真人**：
可疑成绩照常显示，只是不计入最佳、不出分享卡。局限：解包改代码挡不住，只能拖慢——
真正的高分榜仍需要服务端重算。

- **输入真实性**：事件时间戳与回调真实时长的偏差、采样间隔变异系数、重复时间戳占比。
- **行为特征**：中段速度变异系数、起笔/收笔的加减速斜率、径向残差低频能量占比、
  二阶差分粗糙度（人手必有微颤，程序圆过于干净）。
- **轨迹指纹**：取 64 个等距样本的归一化径向残差（`number[64]`，非哈希），与本地最近 50 局
  逐元素求平均绝对偏差，识别「重放同一形状」。
- **存档自校验**：最佳成绩同时保存笔迹；读取时重算分数，对不上说明分数被改过。
- **判定策略**：风险分 ≥10 且命中 ≥2 条 → 判 `shadow`（不计入最佳）；≥5 → 判 `unverified`（不出分享卡）。
  单条弱信号不定罪——真人笔迹实测风险分 3，机器笔迹 18。

## 可测试化

纯函数集中在 `shared/scoring.js`（24 个导出符号），`game.js` 末尾以 `module.exports` 转出同一批符号
（`evaluate / resample / kasaFit / winding / roundScore / closeFactor / largestGap / getRank /
diagnose / upgradeTip / guardCheck / shapeSig / isReplay / stat / judge / encodePts / decodePts /
fnv / BEST_SALT / RANKS / SCORE_CFG / GUARD_CFG / INVALID_TIPS`），Node 下 `require` 即可跑单测，
无需画布；浏览器分支的输入绑定在无 `window` 时直接跳过。

`shared/scoring.js` 与 `game.js` 导出的是**同一批函数对象**（不是副本），
`unit/shared.test.js` 用 `===` 断言这一点——防止有人又在 `game.js` 里留一份本地副本导致两端算法漂移。

## 小游戏适配要点

- 图片加载走 `wx.createImage()`，小游戏环境无全局 `Image`。
- 屏幕信息走 `wx.getWindowInfo()`，低版本基础库回退 `wx.getSystemInfoSync()`。
- v0.3 已移除全部音频：不需要 `InnerAudioContext`、不需要 WebAudio、不需要音频素材。
- 触摸事件 clientX 是逻辑 px，需乘 `canvas.width / windowWidth` 换算成物理 px 再进统一坐标转换。
- `index.html` / `README.md` / `.eslintrc.js` 已在 `packOptions.ignore` 中排除，不进包。
